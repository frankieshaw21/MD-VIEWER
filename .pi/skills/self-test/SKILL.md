# 修改后自测

1. 阅读仓库 `.agent/testing.md`，核对当前修改与 `git diff`，不要覆盖已有未提交修改。
2. 每次修改后至少运行 `git diff --check`，并检查改动是否符合用户要求；仅修改文档时检查链接和文字。
3. 修改 JS 时对相关文件执行 `node --check`；修改桌面宿主或正式页面时，在可用的 Windows/.NET 8 环境运行 `powershell -NoProfile -ExecutionPolicy Bypass -File ./desktop/build.ps1`。浏览器页面改动还应按需在浏览器检查。
4. 涉及界面或交互时，尽可能运行最新构建，用临时文件验证改动对应的实际行为；不要把构建成功当成运行验证，也不要以旧安装版替代新构建。不要操作真实用户文档，不要未经请求安装或发布。
5. 缺少依赖、无法启动或无法人工验证时，记录尝试、障碍与未验证项，不能宣称已通过。交付时区分静态检查、构建、运行验证与未验证事项。
