# 体验与性能复查

## 范围与验证方式

- 分支 `feature/md-viewer-performance`，开始时工作区干净。
- 阅读正式前端的编辑、源码辅助、文件会话、UI 与 Markdown 标题解析路径，核对桌面启动与桥接关键代码及既有整体回归记录。
- Edge headless，通过 CDP 加载当前仓库正式 `md-viewer.html`，使用独立临时用户目录、内存 File 对象。调用真实应用端口和 input 事件；没有安装、发布或改写用户文档。
- 全部 `js/*.js` 的 `node --check` 通过。
- 本轮未修改应用代码，未重新构建或运行桌面 WebView2。数据是浏览器单次同步处理时间，不是桌面基准、键盘端到端延迟或 P95。

## 实测性能（ms）

样本文本重复包含标题、中文、粗体、列表；标题密度很高。各子步骤单独执行，不应把耗时相加推导总耗时。渲染测量含 addFile 的历史操作；不保证 Mermaid 等异步增强已完成。

| 字符数 | 打开/渲染 | 切到源码 | input 派发 | 单独重建大纲 | 单独源码刷新 | 回预览 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 54,000 | 98 | 336 | 169 | 8 | 121 | 253 |
| 270,000 | 553 | 591 | 72 | 45 | 1 | 1,221 |
| 918,000 | 1,478 | 1,348 | 118 | 129 | 4 | 2,959 |

超过 250,000 字符的原生纯文本源码降级确实避开全量高亮开销，但大纲与预览仍然昂贵。不同次测量受布局状态影响，大纲单独耗时大于 input 总耗时不构成矛盾；不能据此宣称精确成本占比。

## 优化优先级

### P1：中型文档每次输入全量高亮

`js/source-tools.js` 的 input 监听直接调用 refresh；低于降级阈值时重建高亮与行号并测量当前行。54,000 字符样本单独刷新约 121 ms，容易影响连续输入。

建议先合并一帧内刷新或短防抖，并在 IME 组合输入期间避免重建；随后做可见区高亮/增量更新。不要单纯扩大纯文本降级范围而隐藏功能取舍。需真实键盘、中文 IME 与选区对齐回归。

### P1：源码输入同步重建全部大纲

`js/editor.js` sourceChanged 每次输入直接 updateOutline；parser.extractHeadings 扫描全文，并为每个标题创建临时 DOM 解析行内文本，再删除并重建全部大纲项。

建议复用已有 scheduleOutline 合并输入，进一步缓存标题解析和条目、只更新变化项。计数也可延迟合并；文件内容和脏标记仍应及时更新，保存前必须取得最新文本。

### P1：模式往返无修改也重新渲染预览

changeViewMode 回预览总是 loadMarkdown，重新生成全部 DOM、增强、计数和大纲。918,000 字符样本回预览约 2.96 秒。

建议记录预览对应的文档标识、内容修订号与外观修订号；只在同文档、源码未变、渲染配置未变时复用预览。不能只比较全局模式，以免切换标签或主题后复用错误内容。大文档真正更新时仍需分块/后台解析，并给出处理反馈。

### P2：折叠标题使大纲当前项跟踪错误（源码问题；原探针不精确）

原测试输入包含 First、关闭的 details 内的 Hidden heading、其后的 Visible heading，大纲两项仍把 First 标成当前项。但后续发现 `h2:last-of-type` 也匹配隐藏标题，不能作为准确复现证据；更正及修复后严格回归见 [优化验证](performance-optimization.md)。

getOutline 排除关闭 details 中的标题，但 updateActiveHeading 遍历全部标题并使用 DOM 索引对应过滤后的列表；隐藏标题的位置还可能提前终止扫描。应共用同一份可见标题映射，并在折叠、展开、内容变化后失效缓存。滚动时只切换前后两项 class，避免每次遍历全部大纲条目。

### P2：会话容量失败反馈不足（源码风险，未故障注入）

files.saveSession 同步 JSON.stringify + localStorage 存全部标签内容；配额失败仅 console.warn。prepareExit 将持久化失败作为 false 返回，可能同时影响退出体验。

建议在用户可见区域说明“草稿恢复不可用”，明确磁盘保存仍是否成功；评估将全文会话移到 IndexedDB，localStorage 只保留索引。需配额不足、多大文档标签、关闭窗口测试，不应删除草稿来静默避错。

### P2：同名浏览器文件身份混淆（部分验证）

files.addFile 按 name 去重，两个目录的同名文件无法独立成标签。测试在活动源码有未保存草稿时重新添加同名、不同内容 File：旧草稿仍保留，但传入文件没有作为新标签打开。代码同时先覆盖记录再 switchFile，存在新文件基线/句柄与旧编辑内容混合的风险。

需要以句柄 isSameEntry 或可靠身份区分，无法区分时明确询问用户；本轮未执行系统文件选择器和真实覆盖保存，不能声称已复现磁盘误写。

## 建议顺序与未覆盖项

先解决源码输入全量刷新和大纲同步重建，再修正折叠标题映射，随后引入预览修订缓存。会话存储迁移属于更大范围改动，单独设计和验证。

本轮未覆盖桌面运行、安装/更新、真实中文输入与系统剪贴板、实际滚动帧率、长时间内存稳定性、外部文件并发、配额故障。测试页面已关闭；临时测试驱动保存在系统临时目录，不是仓库可重复运行的自动化测试套件。
