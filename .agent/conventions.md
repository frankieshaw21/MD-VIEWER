# 开发规范与约束

- 优先阅读 `CONTRIBUTING.md`；一次改动尽量聚焦一个目标。变更 UI 时更新实际页面和样式，不仅修改 `demo/`；如影响使用方法，同步维护 `README.md` 和 `desktop/README.md`。
- 正式前端运行时无需 Node.js、npm 或外部 CDN；保留离线使用能力。`mermaid.min.js` 是本地资源。修改 CSS/JS 后检查 `md-viewer.html` 中的资源版本参数，避免浏览器旧缓存。
- 前端模块通过 `context` 的状态、端口与事件协作；新功能先检查现有 `js/bootstrap.js` 注册和启动顺序、DOM ID、全局命令桥接，不要在模块间引入隐式依赖。桌面文件操作应通过 `js/desktop.js` 和 `desktop/MainForm.cs` 的授权边界。
- 编辑或保存逻辑要兼顾预览、源码、分屏、多标签、未保存状态、外部修改及历史快照。测试必须使用临时文档，不覆盖用户实际文件。
- 不提交密码、私钥、证书、含敏感信息的测试文件或构建输出。`VERSION`、`CHANGELOG.md` 与发布标签保持一致；标签触发的 CI 是构建发布，不代表已验证干净 Windows 环境的安装。
- 文档说明应区分“已经验证”与“待确认”；未经执行不可声称已提交、已推送或已发布。
